# 成果物の検査基準

PRを、作成の経緯を知らない読み手がそのまま読める状態にするための基準。

判定の問いは一つである。「この記述は、作業中の会話や試行錯誤を知らない読み手の役に立つか」。役に立たない記述は、作業の名残として取り除く。

## 検査対象

- PRのdiffで追加または変更された行
  - コード
  - コードコメント
  - 文書
- PRのtitleとdescription
- PRに含まれるcommitのメッセージ

diffに現れない既存の行は検査しない。

## 見つけるもの

### 作業の名残の種類と直し方

| 種類 | 典型的な現れ方 | 直し方 |
|---|---|---|
| 依頼や指示への言及 | 「ご指摘のとおり」「依頼に基づき」「要件を満たすため」 | 言及を削り、内容だけを残す |
| 変更経緯の説明 | 「以前は〜だった」「〜から変更した」 | 現在の姿だけを書く |
| 採らなかった方法の表明 | 「〜は使わない」「〜を避けるため」 | 採った方法だけを書く |
| 作成者向けのメモ | 自分宛のTODO、検討中の覚え書き | 削る |
| 作業過程の残骸 | デバッグ出力、コメントアウトした旧コード、一時ファイル | 削る |
| 会話から流用した例 | 意図を伝えるために出た例が、そのまま本文の題材になっている | 成果物の読み手に合う例へ差し替えるか、削る |
| 継ぎはぎの跡 | 用語、文体、前提が箇所ごとに食い違う | 全体を一つの書き方に揃える |
| 作業環境の情報 | ローカルの絶対パス、セッションのURL、個人の端末名 | 削るか、読み手の環境で通じる表現に直す |

### 経緯を書いてよい場所

commitメッセージ、変更履歴、ADRは、変更の経緯を記録する場所である。これらに書かれた経緯は名残として扱わない。依頼や会話への言及は、これらの場所でも取り除く。

## 残すもの

読み手が知らないと誤るおそれのある情報は残す。互換性の注意、既知の制限、前提とする環境が該当する。対象リポジトリや実行環境の規約が付けると定めている署名や帰属表示も残す。迷ったら、その一文を消したときに読み手が困るかで決める。

## 直し方の原則

- 説明を足さず、書き換える。名残を消した理由を成果物に書かない。
- 制約は成果物の作りに反映する。「初心者向けに書く」という条件は、用語の説明や手順の細かさで満たす。条件そのものは書かない。
- 削るだけで意味が通るなら削る。前後の文がつながらなくなる場合だけ書き直す。
- 技術的な正しさと、読み手が必要とする要件は変えない。
